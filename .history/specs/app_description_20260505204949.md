# Expenses App — Product & Technical Specification (v1.0 FINAL)

---

# 1. Core Design

The system is an **event-sourced, append-only ledger**.

All state is derived by deterministic replay of events.
There is no mutable financial state.

```text id="state_model"
state = replay(sorted(events))
```

---

# 2. Tech Stack

* UI: Streamlit
* Backend: Python 3.10+
* Storage: Google Sheets (append-only event log)
* Charts: matplotlib / plotly
* Utils: uuid4, time.time_ns(), datetime (Israel timezone)

---

# 3. Data Model

## 3.1 Events (source of truth)

```text id="events_schema"
event_id | request_id | timestamp_ns | type | payload_json
```

### Event types

* EXPENSE_CREATED
* EXPENSE_EDITED
* EXPENSE_DELETED
* SETTLEMENT_CREATED

---

## 3.2 Idempotency

* No separate table
* Fully embedded via `request_id` in events

---

# 4. Write Protocol (STRICT)

Each operation:

1. Generate `request_id` (uuid4.hex)
2. Append event to Google Sheets
3. Confirm write success
4. Rely on idempotency on future retries

---

# 5. Event Store Behavior

## 5.1 Startup loading

* Single **batch read of full sheet**
* Parse into memory

No row-by-row reads allowed.

---

## 5.2 Ordering invariant (MANDATORY)

All processing must use:

```text id="ordering"
sort(events, key=(timestamp_ns, event_id))
```

Sheet row order is irrelevant.

---

# 6. Idempotency

## Rule

If `request_id` already exists → ignore event.

## Implementation

* In-memory index:

  * `request_id → event_id`
* Rebuilt on startup via full scan

---

## Constraint

* `request_id` is globally unique
* generated via `uuid4().hex`
* never reused

---

# 7. Recovery Semantics

* System always rebuilds from events on startup
* No repair logic required

---

# 8. Expense Model

```json id="expense_model"
{
  "amount": 100,
  "payer": "userA",
  "splits": {
    "userA": 60,
    "userB": 40
  },
  "category": "Food"
}
```

### Invariant

```text id="split_invariant"
sum(splits) == amount
```

---

# 9. Expense Semantics

## 9.1 Creation

Full snapshot event.

---

## 9.2 Edit

* emits EXPENSE_EDITED
* replaces full expense state (no patching)

---

## 9.3 Delete

* emits EXPENSE_DELETED
* globally overrides expense

---

## 9.4 Resolution (STRICT ORDERED RULE)

For each `expense_id`:

1. Sort events by `(timestamp_ns, event_id)`
2. If any `EXPENSE_DELETED` exists → expense = NULL
3. Else → last event wins

```text id="resolution_rule"
group_by(expense_id) → sort → apply rules → derive state
```

---

# 10. Settlement Model

```json id="settlement_model"
{
  "from": "userA",
  "to": "userB",
  "amount": 100
}
```

### Properties

* first-class event
* included in replay
* affects balances directly
* visible in history + timeline

---

# 11. Balance Computation

For each user:

* sum owed via splits
* minus debts
* apply settlements

Fully derived from replayed event state.

---

# 12. Replay Engine

## Property

```text id="replay_property"
replay(events) is pure
```

* no external state
* deterministic output
* identical input → identical state

---

## Rule

Final state depends only on **sorted event log**

---

# 13. Performance Model

## Startup

* full batch load
* in-memory parse + sort

## Runtime

* incremental reuse via cache (optional)

---

# 14. Replay Cache

Cache valid iff:

* event append succeeded
* request_id confirmed in memory index

### Constraints

* process-local only
* invalidated on restart
* no persistence across sessions

Else:

* full replay fallback

---

# 15. Currency Model

* integer-only (smallest currency unit)
* no floats anywhere in backend
* frontend only formats display

---

# 16. Rules Engine

```text id="rule_schema"
keyword | category | priority | order_index
```

### Deterministic resolution

1. highest priority wins
2. tie → lowest order_index
3. tie → lexicographic keyword order

---

# 17. UI Model (Streamlit)

* fully stateless
* every action emits event
* state always derived via replay
* UI never mutates state directly

---

# 18. System Invariants

* append-only event log
* deterministic sorting required
* idempotency via request_id
* delete overrides all edits
* settlement is first-class event
* integer-only money representation
* replay is pure function
* full reconstruction always possible from Sheets
