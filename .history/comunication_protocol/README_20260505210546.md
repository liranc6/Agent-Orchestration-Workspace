# Communication Protocol

Goal: text-only, minimal tokens, fast meaning.

## Rules

- Text only. No calls, no long docs in chat.
- Use short tokens and shorthand.
- Use only what is needed.
- No need for perfect grammar.

## Format

- `role: msg`
- `task: short` or `note: short`
- `Q?` for questions, `A:` for answers, `ACK` for receipt.
- `BLOCK` when stuck.
- `DONE` when finished.
- `WIP` for work in progress.
- `FYI` for info only.
- `PR` for pull request.
- `UX`, `DEV`, `QA`, `PM`, `OPS`, `REVIEW` as prefixes when useful.

## Examples

- `DEV: task: fix invoice calc`  
- `PM: Q? confirm currency fallback`  
- `QA: BLOCK env failing tests`  
- `REVIEW: PR#12 ready`  
- `OPS: deploy prod 22:00`  
- `UX: note: mobile layout edge-case`

## Priorities

- `URGENT` only for blocking issues.
- Prefer direct concise statements.
- If more than 2 lines needed, move to doc and send link.

## When to use docs

- `doc: <short description>` plus link.
- Keep docs separate from chat.
- Use chat only for coordination.

## Team style

- Prefer `ok` / `ack` / `got it`.
- Avoid paragraphs.
- Ask clarifying question fast.
- If unclear, send `Q?` with one sentence.

## Token shorthand

- `FYI` = for your info
- `ETA` = estimated time
- `TBD` = to be decided
- `N/A` = not applicable
- `TBC` = to be clarified
- `ASAP` = as soon as possible

## Example flow

- `PM: task: add split-expense`  
- `DEV: ack, WIP`  
- `DEV: Q? how handle empty notes`  
- `PM: use "none"`  
- `DEV: DONE`  
- `REVIEW: ACK`  
- `QA: TEST PASS`
